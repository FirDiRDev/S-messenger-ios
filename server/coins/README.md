# Сервер монет S-messenger (ЮMoney)

Покупка монет за рубли: «Стартовый» 99 ₽ → 250, «Горсть» 150 ₽ → 300, «Мешок» 300 ₽ → 600, «Сундук» 500 ₽ → 1500, «Клад» 1000 ₽ → 3500.
«Фишки для Блэкджека» (те же монеты): «Стопка фишек» 249 ₽ → 700, «Кейс крупье» 749 ₽ → 2400, «Хайроллер» 1490 ₽ → 5500.
`GET /api/packs` - список паков сервера (приложение показывает паки фишек, только если сервер их знает).
Проще без своего хостинга - вариант на Cloudflare Workers: `../coins-worker` (см. `../README.md`).

## Почему нужен сервер
ЮMoney сообщает об оплате HTTP-уведомлением на публичный HTTPS-адрес. Телефон такой адрес
принять не может, поэтому платёж принимает этот маленький сервер, а монеты на телефон
приходят подписанным чеком. Подделать чек нельзя: подпись делается закрытым ключом,
который есть только на сервере, а приложение проверяет её открытым ключом.

## Запуск
1. `pip install flask cryptography`
2. Заполните `config.py`: номер кошелька, секретное слово, адрес сервера.
3. `python keys.py` - создаст `receipt_private.pem` и напечатает открытый ключ.
4. Добавьте в `update.json` блок `coinShop` (см. `../README.md`): `wallet`, `server`,
   `publicKey` - магазин включится у всех без новой сборки приложения.
5. В ЮMoney: https://yoomoney.ru/transfer/myservices/http-notification - адрес
   `https://ВАШ-СЕРВЕР/yoomoney/notify`, секретное слово - то же, что в `config.py`.
   Нажмите «Протестировать» - в базе появится запись со статусом `test`.
6. Запустите `python server.py` (лучше: gunicorn за nginx с HTTPS-сертификатом).

## Защита от обмана
- подпись уведомления SHA-1 с секретным словом (неверная - 403, ничего не начисляется);
- каждый `operation_id` обрабатывается один раз (повторы уведомлений не удваивают монеты);
- переводы с протекцией (`codepro`), незачисленные (`unaccepted`) и не в рублях - не начисляются;
- пак выбирается по точной сумме, которую заплатил человек (`withdraw_amount`, в копейках);
  сумма не совпала ни с одним паком - платёж сохраняется со статусом `unmatched` для ручной проверки;
- в `label` уходит секретный ID покупок игрока (64 hex): он создаётся в приложении один раз,
  хранится в защищённой базе `coin_purchases.db` и переносится с экспортом профиля;
- чеки подписаны ECDSA P-256; приложение зачисляет чек только своему ID, только на сумму
  своего пака и только один раз (номер чека и номер платежа уникальны в базе).

Не выкладывайте `config.py` с секретом и `receipt_private.pem` в открытый доступ.
