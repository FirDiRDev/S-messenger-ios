# StoykoMessenger (S-messenger)

P2P-мессенджер для Android: текст, файлы, аудиозвонки. Без центрального сервера,
сквозное шифрование (libsodium). Основан на aTox (GPL-3.0; исходный проект больше
не поддерживается), протокол Tox — совместим с qTox и другими Tox-клиентами,
в том числе на Windows.

## Сборка одной кнопкой (Windows)

Запустите `build_apk.bat` из корня проекта — он сам найдёт Android Studio, JDK и SDK
(если SDK нет — скачает сам), возьмёт уже установленную платформу Android 35+
и положит готовые APK в папку `APK`.

### Если сеть рвёт соединения с Google/Maven

`build_apk.bat` сначала отдельно скачивает все зависимости (задача `smPrefetch`),
повторяя до 10 раз и чередуя основные серверы с зеркалом `maven.aliyun.com`, а потом
собирает APK с `--offline`. Скачанное хранится в `%USERPROFILE%\.gradle` и
перекачивается только при обновлении версий.

Если серверы недоступны совсем: включите VPN на время первой сборки или создайте
в корне проекта `proxy.txt` с одной строкой `host:port` HTTP-прокси (образец —
`proxy.txt.example`, например локальный VPN-клиент `127.0.0.1:10809`).

## Сборка APK в Android Studio (Windows)

1. Установите свежую Android Studio (2025.2 или новее; нужна поддержка AGP 9).
2. `File → Open` → выберите папку `StoykoMessenger` (где лежит `settings.gradle.kts`).
3. Дождитесь Gradle Sync. Используется JDK из Android Studio; нативная часть toxcore
   уже лежит в проекте (см. «Нативная часть»).
4. Отладочный APK: `Build → Build App Bundle(s) / APK(s) → Build APK(s)`
   → `app/build/outputs/apk/debug/app-debug.apk`.
5. Релизный APK: в терминале Android Studio
   ```
   gradlew.bat :app:assembleRelease
   ```
   → `app/build/outputs/apk/release/app-release.apk`.
   Без `keystore.properties` он подписан debug-ключом (ставится на телефон,
   но для публикации создайте свой ключ: `Build → Generate Signed App Bundle / APK`
   и заполните `keystore.properties` по образцу в `app/build.gradle.kts`).

Visual Studio этот проект собрать не может (Kotlin/Gradle).

## Нативная часть (toxcore)

Сетевое ядро — готовая библиотека `libjni-c-toxcore.so` из проекта
[TRIfA](https://github.com/zoff99/ToxAndroidRefImpl) (jni-c-toxcore 1.0.201, ветка
`zoff99/maven_artefact`), уже положенная в `domain/src/main/jniLibs/` для
arm64-v8a, armeabi-v7a, x86 и x86_64 (отладочная информация удалена). Внутри —
c-toxcore, toxav, libsodium, opus, libvpx. Linux, NDK и сборка C-кода не нужны.

Библиотека привязана к имени Java-класса `com.zoffcc.applications.trifa.MainActivity`
(`domain/src/main/java/com/zoffcc/...`) — это мост JNI, а не экран приложения.
Имена и сигнатуры методов в нём менять нельзя. Обёртка для остального кода —
`domain/src/main/kotlin/tox/ToxWrapper.kt`.

Обновить библиотеку: взять `stubaar/jni/<abi>/libjni-c-toxcore.so` из новой версии
ветки `zoff99/maven_artefact`, при желании уменьшить `llvm-strip --strip-unneeded`,
и сверить сигнатуры колбэков в `jni-c-toxcore.c` с `MainActivity.java`.

## Что изменено относительно aTox

- Название/пакет: `com.stoyko.smessenger`, имя в лаунчере «S-messenger», новая иконка.
- Удалено устаревшее: Bazel, fastlane/F-Droid, detekt, старый CI, tox4j и Linux-скрипты
  его сборки. Ядро Tox — готовая библиотека TRIfA (см. «Нативная часть»).
- Прокси: поддерживается только SOCKS5 (HTTP-прокси нативная библиотека не умеет).
- minSdk 21 (Android 5.0+), targetSdk 35; APK под armeabi-v7a, arm64-v8a, x86, x86_64 + универсальный.
- Список узлов обновлён (сентябрь 2026), узлы с TCP 443 используются первыми.
- Сеть:
  - каждый узел регистрируется как TCP-релей на всех его портах (443 первым);
  - принимаются узлы только с TCP (раньше отбрасывались);
  - 8 узлов за раз вместо 4, повтор каждые 10–30 с при отсутствии связи;
  - UDP по умолчанию включён → поиск собеседников в локальной сети и прямые звонки;
  - MulticastLock для обнаружения в Wi-Fi без интернета;
  - исправлены падения: Toast из фонового потока, отсутствующий user_nodes.json,
    обращение к ещё не загруженному списку узлов.

## Работа в сетях с ограничениями («белые списки»)

Ни одно приложение не может гарантировать связь, если сеть пропускает только
заранее разрешённые адреса. Что реально работает, по порядку надёжности:

1. **Одна локальная сеть** (Wi-Fi роутер, точка доступа с телефона) — интернет не нужен.
   Оба устройства в одной сети, UDP включён — контакты находят друг друга сами,
   работают сообщения, файлы и звонки.
2. **Свой релей** на сервере, который доступен из вашей сети, на порту 443
   (конфиг: `docs/relay/tox-bootstrapd.conf`). В приложении:
   Настройки → Источник начальных узлов → Пользовательские → файл по образцу
   `docs/my_nodes.example.json` с адресом и ключом вашего узла.
3. **Прокси** SOCKS5/HTTP (Настройки → Прокси), если у вас есть доступный прокси.
   При включённом прокси UDP отключается, весь трафик идёт через него.

Если ни один из путей не доступен, связь через интернет невозможна — это
ограничение сети, а не приложения.
